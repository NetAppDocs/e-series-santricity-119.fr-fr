[[how-does-asynchronous-mirroring-differ-from-synchronous-mirroring]]
== En quoi la mise en miroir asynchrone diffère-t-elle de la mise en miroir synchrone ?

La fonction de mise en miroir asynchrone diffère de la fonction de mise en miroir synchrone sur un point essentiel : elle capture l’état du volume source à un instant précis et copie uniquement les données qui ont changé depuis la dernière capture d’image.

Avec la mise en miroir synchrone, l'état du volume principal n'est pas capturé à un instant précis, mais reflète toutes les modifications qui ont été apportées au volume principal sur le volume secondaire. Le volume secondaire est identique au volume principal à chaque instant car, avec ce type de miroir, chaque fois qu'une écriture est effectuée sur le volume principal, une écriture est effectuée sur le volume secondaire. L'hôte ne reçoit pas d'accusé de réception indiquant que l'écriture a réussi tant que le volume secondaire n'a pas été mis à jour avec succès avec les modifications qui ont été apportées au volume principal.

Avec la mise en miroir asynchrone, la baie de stockage distante n'est pas entièrement synchronisée avec la baie de stockage locale, donc si l'application doit basculer vers la baie de stockage distante en raison d'une perte de la baie de stockage locale, certaines transactions pourraient être perdues.

Comparaison des fonctionnalités de mise en miroir :

[cols="1a,1a"]
|===
| Mise en miroir asynchrone | Mise en miroir synchrone 


 a| 
*Méthode de réplication*



 a| 
* *Point-in-Time*
+
La synchronisation s'effectue à la demande ou automatiquement selon une planification définie par l'utilisateur. Les planifications peuvent être définies à la granularité de la minute. Le temps minimum entre les synchronisations est de 10 minutes.


 a| 
* *Continue*
+
La mise en miroir est exécutée automatiquement en continu, copiant les données de chaque écriture de l'hôte.





 a| 
*Capacité réservée*



 a| 
* *Plusieurs*
+
Un volume de capacité réservé est requis pour chaque paire en miroir.


 a| 
* *Unique*
+
Un seul volume de capacité réservée est requis pour tous les volumes mis en miroir.





 a| 
*Communication*



 a| 
* *iSCSI et Fibre Channel*
+
Prend en charge les interfaces iSCSI et Fibre Channel entre les baies de stockage.


 a| 
* *Fibre Channel*
+
Prend uniquement en charge les interfaces Fibre Channel entre les baies de stockage.





 a| 
*Distance*



 a| 
* *Illimité*
+
Prise en charge de distances pratiquement illimitées entre la baie de stockage locale et la baie de stockage distante, la distance étant généralement limitée uniquement par les capacités du réseau et la technologie d'extension de canal.


 a| 
* *Restreint*
+
Il doit généralement se trouver à environ 10 km (6,2 miles) de la baie de stockage locale pour répondre aux exigences de latence et de performance de l'application.



|===


[[why-cant-i-access-my-chosen-mirroring-feature]]
== Pourquoi ne puis-je pas accéder à la fonction de mirroring que j'ai choisie ?

La mise en miroir est configurée dans l'interface SANtricity Unified Manager.

[NOTE]
====
La mise en miroir synchrone n'est pas disponible sur la baie de stockage EF600/EF600C ou EF300/EF300C.

====
Pour activer et configurer la mise en miroir entre deux baies, vérifiez les éléments suivants :

* Le service Web Services Proxy doit être en cours d'exécution. (Unified Manager est installé sur un système hôte en même temps que le Web Services Proxy.)
* Unified Manager doit être exécuté sur votre hôte local via une connexion HTTPS.
* Les deux baies de stockage que vous souhaitez utiliser pour la mise en miroir doivent être découvertes dans Unified Manager.
* Unified Manager doit disposer de certificats SSL valides pour les baies de stockage. Vous pouvez accepter un certificat auto-signé ou installer des certificats signés par une autorité de certification depuis Unified Manager.


Pour les instructions de configuration, voir ce qui suit :

* link:../um-manage/create-asynchronous-mirrored-pair-um.html["Créer une paire miroir asynchrone (dans Unified Manager)"]
* link:../um-manage/create-synchronous-mirrored-pair-um.html["Créer une paire miroir synchrone (dans Unified Manager)"]




[[what-do-i-need-to-know-before-creating-a-mirror-consistency-group]]
== Que dois-je savoir avant de créer un groupe de cohérence miroir ?

Suivez ces instructions avant de créer un groupe de cohérence.

[NOTE]
====
La mise en miroir synchrone n'est pas disponible sur le système de stockage EF600/EF600C ou EF300/EF300C.

====
Vous créez un groupe de cohérence dans Unified Manager dans l'assistant Créer des paires miroir.

Respectez les exigences suivantes pour Unified Manager :

* Le service Web Services Proxy doit être en cours d'exécution.
* Unified Manager doit être exécuté sur votre hôte local via une connexion HTTPS.
* Unified Manager doit afficher des certificats SSL valides pour la baie de stockage. Vous pouvez accepter un certificat auto-signé ou installer votre propre certificat de sécurité à l'aide de Unified Manager et en accédant à menu:Certificate[Certificate Management].


Veillez également à respecter les exigences suivantes pour les baies de stockage :

* Les deux baies de stockage doivent être détectées dans Unified Manager.
* Chaque baie de stockage doit comporter deux contrôleurs.
* Chaque contrôleur dans la matrice principale et la matrice secondaire doit avoir un port de gestion Ethernet configuré et doit être connecté à votre réseau.
* Les baies de stockage ont une version minimale de firmware de 7.84. (Elles peuvent chacune exécuter des versions différentes du système d'exploitation.)
* Vous devez connaître le mot de passe pour les baies de stockage locales et distantes.
* Vos baies de stockage locales et distantes sont connectées via une structure Fibre Channel ou une interface iSCSI.




[[asynchronous-mirroring-what-do-i-need-to-know-before-creating-a-mirrored-pair]]
== Mise en miroir asynchrone - Que dois-je savoir avant de créer une paire en miroir ?

Vous configurez les paires en miroir dans l'interface SANtricity Unified Manager, puis vous gérez les paires dans SANtricity System Manager.

Avant de créer une paire symétrique, suivez ces directives.

* Vous devez disposer de deux baies de stockage.
* Chaque baie de stockage doit comporter deux contrôleurs.
* Chaque contrôleur dans la matrice principale et la matrice secondaire doit avoir un port de gestion Ethernet configuré et doit être connecté à votre réseau.
* Vos baies de stockage locales et distantes sont connectées via une structure Fibre Channel ou une interface iSCSI.
* Les baies de stockage ont une version minimale de firmware de 7.84. (Elles peuvent chacune exécuter des versions différentes du système d'exploitation.)
* Vous devez connaître le mot de passe pour les baies de stockage locales et distantes.
* Vous devez disposer d'une capacité libre suffisante sur la baie de stockage distante pour créer un volume secondaire égal ou supérieur au volume principal que vous souhaitez mettre en miroir.
* Vous avez installé le proxy de services Web et Unified Manager. Les paires miroir sont configurées dans l'interface Unified Manager.
* Les deux baies de stockage sont détectées dans Unified Manager.
* Votre baie de stockage doit contenir au moins un groupe de cohérence miroir. Vous créez un groupe de cohérence dans Unified Manager dans l'assistant Créer des paires miroir.




[[what-do-i-need-to-know-before-increasing-my-reserved-capacity-on-a-mirrored-pair-volume]]
== Que dois-je savoir avant d’augmenter ma capacité réservée sur un volume de paire miroir ?

En règle générale, vous devez augmenter la capacité réservée lorsque vous recevez un avertissement indiquant que la capacité réservée pour une paire en miroir est presque pleine. Vous pouvez augmenter la capacité réservée uniquement par incréments de 8 Gio.

Pour les opérations de mise en miroir asynchrones, la capacité réservée représente généralement 20 % du volume de base. Choisissez une capacité réservée plus importante si l'une ou les deux conditions suivantes existent :

* Vous comptez conserver la paire symétrique pendant une longue période.
* Un pourcentage important de blocs de données sera modifié sur le volume principal en raison d'une forte activité d'E/S. Utilisez les données historiques de performance ou d'autres utilitaires du système d'exploitation pour vous aider à déterminer l'activité d'E/S typique sur le volume principal.


Vous pouvez augmenter la capacité réservée pour une paire miroir en effectuant l'une des actions suivantes :

* Ajustez le pourcentage de capacité d'un volume de paire en miroir en sélectionnant menu:Storage[Pools and Volumes Groups] puis en cliquant sur l'onglet *Reserved Capacity*.
* Créez un nouveau volume en utilisant la capacité libre qui est disponible sur un pool ou un groupe de volumes.
+
Si aucune capacité libre n'existe sur un pool ou un groupe de volumes, vous pouvez ajouter de la capacité non configurée sous forme de disques inutilisés à un pool ou un groupe de volumes.





[[why-cant-i-increase-reserved-capacity-with-my-requested-amount]]
== Pourquoi ne puis-je pas augmenter la capacité réservée avec le montant demandé ?

Vous pouvez augmenter la capacité réservée uniquement par incréments de 4 Gio.

Passez en revue les directives suivantes :

* Vous devez disposer d'une capacité libre suffisante dans le pool ou le groupe de volumes afin de pouvoir l'étendre si nécessaire.
+
S'il n'existe aucune capacité libre sur un pool ou un groupe de volumes, vous pouvez ajouter de la capacité non attribuée sous forme de disques inutilisés à un pool ou un groupe de volumes.

* Le volume du pool ou du groupe de volumes doit avoir un statut optimal et ne doit être dans aucun état de modification.
* Il doit exister de la capacité libre dans le pool ou le groupe de volumes que vous souhaitez utiliser pour augmenter la capacité.


Pour les opérations de mise en miroir asynchrones, la capacité réservée représente généralement 20 % du volume de base. Utilisez un pourcentage plus élevé si vous pensez que le volume de base subira de nombreux changements ou si la durée de vie estimée de l'opération de service de copie d'un objet de stockage sera très longue.



[[why-would-i-change-this-percentage]]
== Pourquoi modifierais-je ce pourcentage

La capacité réservée représente généralement 40 % du volume de base pour les opérations de snapshot et 20 % du volume de base pour les opérations de mise en miroir asynchrone.

Cette capacité est généralement suffisante. La capacité nécessaire varie en fonction de la fréquence et de la taille des écritures d'E/S sur le volume de base et de la durée pendant laquelle vous prévoyez d'utiliser l'opération de service de copie de l'objet de stockage.

En général, choisissez un pourcentage plus élevé pour la capacité réservée si l'une ou les deux conditions suivantes existent :

* Si la durée de vie de l'opération de service de copie d'un objet de stockage particulier sera très longue.
* Si un pourcentage important de blocs de données est modifié sur le volume de base en raison d'une forte activité d'E/S. Utilisez les données de performance historiques ou d'autres utilitaires du système d'exploitation pour déterminer l'activité d'E/S typique sur le volume de base.




[[why-do-i-see-more-than-one-reserved-capacity-candidate]]
== Pourquoi est-ce que je vois plus d'un candidat à la capacité réservée ?

S'il existe plusieurs volumes dans un pool ou un groupe de volumes qui correspondent au pourcentage de capacité que vous avez sélectionné pour l'objet de stockage, vous verrez plusieurs candidats.

Vous pouvez actualiser la liste des candidats recommandés en modifiant le pourcentage d'espace disque physique que vous souhaitez réserver sur le volume de base pour les opérations de service de copie. Les meilleurs candidats s'affichent en fonction de votre sélection.



[[why-do-i-see-not-available-values-displayed-in-the-table]]
== Pourquoi les valeurs « Not Available » s’affichent-elles dans le tableau ?

Le tableau affiche les valeurs Not Available lorsque les données situées sur la baie de stockage distante ne sont pas disponibles pour être affichées.

Pour afficher les données de la baie de stockage distante, lancez System Manager depuis Unified Manager.



[[why-dont-i-see-all-of-my-pools-and-volume-groups]]
== Pourquoi ne vois-je pas tous mes pools et volume groups ?

Lorsque vous créez un volume secondaire pour la paire de volumes miroirs asynchrones, le système affiche une liste de tous les pools et groupes de volumes éligibles pour cette paire de volumes miroirs asynchrones. Tout pool ou groupe de volumes qui n'est pas éligible à être utilisé ne s'affiche pas dans cette liste.

Les pools ou les groupes de volumes peuvent ne pas être admissibles pour l'une des raisons suivantes.

* Les capacités de sécurité d'un pool ou d'un groupe de volumes ne correspondent pas.
* Un pool ou un groupe de volumes se trouve dans un état non optimal.
* La capacité d'un pool ou d'un groupe de volumes est trop faible.




[[asynchronous-mirroring-why-dont-i-see-all-my-volumes]]
== Mise en miroir asynchrone - Pourquoi ne vois-je pas tous mes volumes ?

Lorsque vous sélectionnez un volume principal pour une paire en miroir, une liste affiche tous les volumes éligibles.

Les volumes qui ne sont pas éligibles à l'utilisation ne figurent pas dans cette liste. Les volumes peuvent ne pas être éligibles pour l'une des raisons suivantes :

* Le volume n'est pas optimal.
* Le volume participe déjà à une relation de mise en miroir.
* Pour les volumes fins, l'expansion automatique doit être activée.



NOTE: Pour les contrôleurs EF600 et EF300, les volumes primaire et secondaire d'une paire miroir asynchrone doivent utiliser le même protocole, le même niveau de tiroir, la même taille de segment, le même type de sécurité et le même niveau RAID. Les paires miroir asynchrones non éligibles n'apparaîtront pas dans la liste des volumes disponibles.



[[asynchronous-mirroring-why-dont-i-see-all-the-volumes-on-the-remote-storage-array]]
== Mise en miroir asynchrone - Pourquoi ne vois-je pas tous les volumes sur la baie de stockage distante ?

Lorsque vous sélectionnez un volume secondaire sur la baie de stockage distante, une liste affiche tous les volumes éligibles pour cette paire en miroir.

Les volumes qui ne sont pas éligibles à l'utilisation ne figurent pas dans cette liste. Les volumes peuvent ne pas être éligibles pour l'une des raisons suivantes :

* Le volume n'est pas optimal.
* Le volume participe déjà à une relation de mise en miroir.
* Les attributs de volume fin entre le volume primaire et le volume secondaire ne correspondent pas.
* Si vous utilisez Data Assurance (DA), le volume principal et le volume secondaire doivent avoir les mêmes paramètres DA.
+
** Si le volume principal est activé DA, le volume secondaire doit également être activé DA.
** Si le volume principal n'est pas activé DA, le volume secondaire ne doit pas être activé DA.






[[why-would-i-update-my-remote-storage-arrays-ip-address]]
== Pourquoi devrais-je mettre à jour l'adresse IP de mon système de stockage distant ?

Vous mettez à jour l'adresse IP de votre baie de stockage distante lorsque l'adresse IP d'un port iSCSI change et que la baie de stockage locale est incapable de communiquer avec la baie de stockage distante.

Lors de l'établissement d'une relation de mise en miroir asynchrone avec une connexion iSCSI, les baies de stockage locale et distante enregistrent l'adresse IP de la baie de stockage distante dans la configuration de mise en miroir asynchrone. Si l'adresse IP d'un port iSCSI change, la baie de stockage distante qui tente d'utiliser ce port rencontre une erreur de communication.

La baie de stockage dont l'adresse IP a été modifiée envoie un message à chaque baie de stockage distante associée aux groupes de cohérence de miroir configurés pour la mise en miroir via une connexion iSCSI. Les baies de stockage qui reçoivent ce message mettent automatiquement à jour leur adresse IP cible distante.

Si la baie de stockage dont l'adresse IP a été modifiée ne parvient pas à envoyer son message inter-baies à une baie de stockage distante, le système vous alerte du problème de connectivité. Utilisez l'option Update Remote IP Address pour rétablir la connexion avec la baie de stockage locale.
