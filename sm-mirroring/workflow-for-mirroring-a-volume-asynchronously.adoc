= Mise en miroir asynchrone d'un volume dans le logiciel SANtricity
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Vous configurez la réplication asynchrone en utilisant le workflow suivant.

. Effectuez la configuration initiale dans Unified Manager :
+
.. Sélectionnez la baie de stockage locale comme source pour le transfert de données.
.. Créez ou sélectionnez un groupe de cohérence miroir existant, qui est un conteneur pour le volume principal sur la baie locale et le volume secondaire sur la baie distante. Les volumes principal et secondaire sont appelés la « paire miroir ». Si vous créez le groupe de cohérence miroir pour la première fois, vous devez spécifier si vous souhaitez effectuer des synchronisations manuelles ou planifiées.
.. Sélectionnez un volume principal sur la baie de stockage locale, puis déterminez sa capacité réservée. La capacité réservée correspond à la capacité physique allouée pour l'opération de copie.
.. Sélectionnez une baie de stockage distante comme destination du transfert, un volume secondaire, puis déterminez sa capacité réservée.
.. Démarrez le transfert de données initial du volume principal vers le volume secondaire. Selon la taille du volume, ce transfert initial peut prendre plusieurs heures.


. Vérifiez la progression de la synchronisation initiale :
+
.. Dans Unified Manager, lancez System Manager pour la baie locale.
.. Dans System Manager, consultez l'état de l'opération de mise en miroir. Une fois la mise en miroir terminée, l'état de la paire mise en miroir est "Optimal".


. *Facultatif :* Vous pouvez reprogrammer ou effectuer manuellement les transferts de données suivants dans System Manager. Seuls les blocs nouveaux et modifiés sont transférés du volume principal vers le volume secondaire.
+
[NOTE]
====
Comme la réplication asynchrone est périodique, le système peut consolider les blocs modifiés et préserver la bande passante réseau. L'impact sur le débit d'écriture et la latence d'écriture est minimal.

====
